# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

**Keep this file current.** Whenever you make a major change — a new screen/mode, a new top-level data file, a new persisted `localStorage` key, a change to the pet/BP economy, or anything else a future session would need to know to avoid rediscovering it from scratch — update the relevant section of this file (or add a new one) as part of that change, not as an afterthought. Small tweaks (copy edits, styling tweaks, bug fixes) don't need an update. When in doubt, ask: "if I started a fresh session tomorrow with no memory of this conversation, would this file tell me the truth about the code?" If not, fix it.

## What this is

A Vite + React + TypeScript web app for practicing Chinese-language exam questions (Primary school Chinese / Higher Chinese, Singapore-style "语文应用": cloze, error correction, reading comprehension, dialogue completion, hanyu pinyin, etc.), with a Tamagotchi-style gamification layer (earn BP for correct answers, hatch and grow a pet owl, feed/play with it via a shop + bag). Sound effects are synthesized with the Web Audio API (no external audio assets, except the one animated owl variant's video, whose sound is muxed into its own file) and dictation read-aloud uses the browser's `SpeechSynthesis` API — the app still needs no backend and works fully offline once built/served.

This was originally a single-file static HTML/CSS/vanilla-JS app (`app.js` + `data/*.js` + `styles.css` at the repo root, on this branch's earlier commits); it has since been rewritten onto Vite + React + TypeScript. **The root-level `app.js`, `styles.css`, and any root `data/` directory are gone** — don't recreate files there. Everything now lives under `src/`, and `index.html` loads `/src/main.tsx`.

## Running / testing

Standard Vite/npm project — no test suite (verify changes by running the dev server and clicking through the flow manually):

- `npm install` — install dependencies (React 19, `@supabase/supabase-js` is present as a dependency for a not-yet-built sync layer, see below).
- `npm run dev` — start the Vite dev server.
- `npm run build` — `tsc -b && vite build`; always run this (or at least `npx tsc -b`) after non-trivial changes, since there's no test suite to catch regressions otherwise.
- `npm run lint` — `oxlint`.
- `npm run preview` — serve the production build locally.
- `scripts/slice_owl_sprites.py` — one-off Python helper used to slice a hand-drawn owl sprite sheet into the individual PNGs under `public/owl/`; only relevant if re-generating owl art from a new sheet.

## Architecture

### Data layer (`src/data/`)
- `types.ts` — shared TypeScript interfaces for everything below: `Question` (`MCQQuestion | FillInQuestion | SelfCheckQuestion`), `QuestionGroup`, `Passage`, `GroupResult`/`GroupResultItem`, `HistoryEntry` (`mode`/`categoryCounts` are optional — absent on pre-dashboard-redesign entries, every reader treats a missing value as "no data", never crashes), `PetState` (includes `questionsLifetime`, a lifetime count of individual questions answered, used for the "every 100 questions" achievement), `ShopItem`, `PetStage`, `MoodBucket`, `Achievement`/`AchievementType` (`"fed" | "evolved" | "missionComplete" | "questionsMilestone"`), and the Tingxie JSON-shape interfaces `TingxieVocabItem`/`TingxieSentence`/`TingxieSentenceBankEntry`/`TingxieLesson`/`TingxieLessonIndexEntry` (see the Tingxie section below).
- `tingxie.ts` — Tingxie's data layer: `fetchTingxieLessonIndex()`/`fetchTingxieLesson()` (the app's only runtime `fetch()`s, cached in module-level `Map`s), `tingxieIconEmoji()`'s icon lookup, sentence/queue-building helpers (`tingxieSentenceWords`, `tingxieBlankWord`, `buildTingxieApplyQueue`, `buildTingxiePracticeVocabQueue`/`buildTingxiePracticeSentenceQueue`, `pooledTingxieReview`), and the `TingxieApplyItem`/`TingxiePracticeItem` queue-item types.
- `questions.ts` — the question "database". This is the file to edit when adding/editing practice content:
  - `LESSON_COUNT` — number of lessons shown in the "practice by lesson" picker.
  - `CATEGORIES` — map of category key → `{ label, lessonMode }`. `lessonMode: true` categories are single-sentence items eligible for "practice by lesson"; `lessonMode: false` are passage-based items only offered under "practice by type".
  - `SUBJECTS` — e.g. `["Chinese", "Higher Chinese"]`, used as a filter in the type picker.
  - `QUESTION_GROUPS` — array of all groups. A **group** is either a standalone question (`passage: null`) or a passage plus every question that shares it — always presented and graded together, never split apart. Each has `groupId`, `subject`, `paper`, `section`, `category`, `lessonEligible` + `lessonIds`, `passage`, an optional shared `optionBank` (e.g. dialogue completion — rendered once, questions reference option keys instead of repeating them), and `questions[]` (`qNo`, `marks`, `format`, `text` — supports `__word__` markers rendered as underlined spans via `RichText`/`richText.tsx` — plus format-specific fields: MCQ has `options`/`correctKey`, Fill-in has `accepted`/`displayAnswer`, Long-Answer/Writing-Constrained just has `displayAnswer` and is self-graded by the student).
  - To add a new paper/lesson: append new group objects following an existing group's shape. Bump `LESSON_COUNT` for a new lesson number; add keys to `CATEGORIES` for a new question type. No other file needs to change for new data of the existing shape.
- `pet.ts` — pet/BP tunable config (not per-user state): `PET_STAGES` (6 growth stages: egg/baby/toddler/young/teenager/adult, with `minGrowth` thresholds), `MOOD_DECAY_PER_HOUR`, `BP_AWARD` (per question format), `TINGXIE_BP_AWARD` (per Tingxie activity — see the Tingxie section below), `SHOP_ITEMS` (id/cost/growth/mood), `PET_DEFAULT_STATE`, and the owl-art helpers described below.

### App state layer (`src/state/AppStateContext.tsx`)
`useReducer` + two React Contexts (`AppStateCtx`/`AppDispatchCtx`, read via `useAppState()`/`useAppDispatch()`). `AppState` holds `screen` (`"home" | "lessonPicker" | "typePicker" | "quiz" | "result" | "owl" | "shop" | "bag" | "auth"`), the current quiz session (`mode`, `modeLabel`, `groups`, `groupIndex`, `results`, `submitted`), and picker selections (`selectedSubject`, `selectedCategories`). `App.tsx`'s `ScreenRouter` switches on `state.screen` to render the matching component from `src/components/`. `"auth"` is a routed-to placeholder for a not-yet-built login screen.

Quiz session actions: `START_QUIZ`, `SUBMIT_GROUP`, `UPDATE_ITEM_RESULT` (patches one self-check item's result in place after the student clicks a self-check button — see below), `NEXT_GROUP`, `RESET_TO_HOME` (mirrors the old app's `resetToHome()`: clears session state but keeps `selectedSubject`/`selectedCategories`).

### Screens (`src/components/`)
Each top-level screen is its own component/folder: `Home`, `LessonPicker`, `TypePicker`, `Quiz`, `Result`, `Owl`, `Shop`, `Bag`, `Tingxie` (see below). Shared UI lives in `components/common/`: `Modal.tsx` (`ConfirmModal` — a custom in-page confirm dialog, used instead of `window.confirm` so styling/behavior stays consistent, e.g. leaving a quiz mid-session or clearing history) and `OwlArt.tsx` (see Owl art below).

- **Quiz** (`Quiz.tsx`): groups for the session are shuffled once (`lib/shuffle.ts`) and stepped through one at a time via `state.groupIndex`. Submitting a group calls `gradeGroup` (`lib/grading.ts`), which grades MCQ/Fill-in immediately and returns self-check items (Long-Answer/Writing-Constrained) as `correct: null` until the student clicks a "✓ 我答对了 / ✗ 还需加强" button, which dispatches `UPDATE_ITEM_RESULT`. Each question has a "🔊 听写 Dictation" button (`lib/speech.ts`'s `speakText()`, `SpeechSynthesisUtterance` in `zh-CN`) that reads the question aloud. **Auto-advance:** if every item in a submitted group graded `correct === true` outright, the quiz auto-dispatches `NEXT_GROUP` after a 0.8s pause (with a visible "moving on..." hint on the Next button); anything wrong/skipped, or still awaiting a self-check click, requires the manual click. A pending auto-advance is cancelled if the student clicks Next early or navigates to a new group.
- **Result** (`Result.tsx`): computes the session score, saves it to history (`state/history.ts`, including `mode`/`categoryCounts` for the dashboard below) once on mount, plays `Sound.applause()` on a 100% score or `Sound.encourage()` otherwise, and — in the same once-per-mount effect — calls `usePet().recordQuestionsCompleted()` and logs any newly-crossed `questionsMilestone`/`missionComplete` achievements (see below). The effect is guarded by a `ranRef` (not just an empty dep array) because React 18 StrictMode double-invokes empty-dep effects once on mount in dev, and unlike the old idempotent `saveHistory`-only version, achievement logging is not idempotent.
- **Home** (`Home.tsx`): a dashboard, not just a mode picker. Top to bottom: a greeting, `PetHeroCard` (the whole card is one `<button>` navigating to the Owl screen — no separate Feed button; the Owl screen's own Feed button already does the inventory-aware Bag-vs-Shop routing), `TodayMission`, the Continue Learning section (the two `.mode-card` mode-picker buttons), `ProgressSummary`, `RecentAchievements`, then the last-8 history rows table, each with a per-row delete (`ConfirmModal`) and a "Clear All" action (`state/history.ts`'s `deleteHistoryEntry`/`clearAllHistory`).
- **TodayMission** (`TodayMission.tsx`): two hardcoded, always-clickable `.mission-row` buttons (deliberately not a data-driven list — with only 2 missions that have genuinely different completion checks and click behaviors, hardcoding is simpler than a small-list abstraction). "复习一课 Revise a Lesson" is done-today if any `mode: "lesson"` history entry exists for today (`lib/stats.ts`'s `isLessonMissionComplete`); clicking it always navigates to the Lesson Picker. "阅读练习 Reading Practice" is done-today if at least one group from `READING_MISSION_CATEGORIES` (`cloze`/`comprehension`/`dialogue`/`practical` — deliberately excludes `errorcorrect`) was completed today (`getReadingMissionCount`); clicking it randomly picks 2 of those 4 categories and immediately starts a quiz (`selectTypeSessionGroups`, same as Type Picker would build), no picker screen shown. Both stay clickable when already done — redoing one just won't produce a second `missionComplete` achievement that day (deduped in `achievements.ts`).
- **RecentAchievements** (`RecentAchievements.tsx`): self-contained (loads `state/achievements.ts`'s `loadAchievements()` itself), renders `null` when empty, shows up to 5 most recent rows with a bilingual description resolved from each achievement's `type`/`detail` plus `lib/stats.ts`'s `formatRelativeTime()`.
- **ProgressSummary** (`ProgressSummary.tsx`): today's question count/accuracy (`lib/stats.ts`'s `getTodayStats`) and day streak (`getStreak`, Duolingo-style — counts consecutive local-calendar days with history entries, walking back from today or yesterday).
- **Owl** (`Owl.tsx`): shows growth stage, mood, growth-bar progress to the next stage, and BP. The screen's `<h1>` *is* the owl's name (inline-editable via a pencil button, `renameOwl()`) — there's no separate static title. Links to Shop and Bag (with a live bag-item count).
- **Shop** (`Shop.tsx`): spend BP on `SHOP_ITEMS`; buying calls `buyItem()` (adds to the pet's bag, does **not** apply the effect immediately) and animates the purchased item's emoji flying from its card into a bag-count badge (`lib/throwAnimation.ts`'s `flyItemTo`).
- **Bag** (`Bag.tsx`): lists bagged items; clicking "🎁 送给它 Give" flies the item's emoji from its card onto the owl art (`flyItemTo` again) and only calls `giveItem()` (which applies growth/mood and decrements inventory) once the animation lands.

### Tingxie / 听写 dictation practice (`src/components/Tingxie/`)
A third top-level practice mode, entered via a `.mode-card` on Home (`GO_TO_SCREEN "tingxie"`) — **deliberately independent of the Quiz/Result/`QuestionGroup` pipeline**. It was ported from a separate standalone app (functionality only, not its Tailwind styling or its points-ledger system) and reuses this app's BP/pet economy instead of a second reward system.

- **Local state, not global**: `Tingxie.tsx` mounts its own `TingxieProvider` (`tingxieState.tsx` — a `useReducer` + two Contexts, `useTingxieState()`/`useTingxieDispatch()`, same shape as `AppStateContext.tsx` but scoped entirely to this subtree). `AppStateContext`'s `Screen` union only knows about a single `"tingxie"` entry point; everything that happens after that (lesson selection, which of the 3 activities is active, flip/queue progress) lives in this local reducer and is **not persisted** — leaving the mode resets it, by design (no localStorage key for it).
- **Data loading**: the app's first and only runtime `fetch()` — lesson content is fetched on demand from static JSON in `public/tingxie-lessons/<id>.json` (+ `index.json`) rather than bundled as TS/JSON imports, specifically so new lessons can be dropped in without a rebuild (`src/data/tingxie.ts`'s `fetchTingxieLessonIndex()`/`fetchTingxieLesson()`, each with a small module-level `Map` cache). Every other screen/data file in this app is bundled at build time; this is the one deliberate exception.
- **Three activities per lesson**, switched via tabs in `Tingxie.tsx`'s top bar once a lesson (or custom review) is active:
  - **Learn** (`Learn.tsx`, `subTab: "vocab" | "sentence"`): 学词语 is a 3D flip-card carousel (`TingxieFlipCard.tsx` — a shared `perspective`/`backface-visibility`/`rotateY` shell reused by Apply/Practice too) over `lesson.vocab`; 学默写 is a sentence-reordering game — word chips (`lib/tingxieSentenceWords()` strips punctuation tokens out of `sentence.segments`) are placed into a tray, and placing them in ascending index order (vs. the shuffled `chipOrder`) is what "correct" means, so the reducer never has to store or re-derive the actual word sequence.
  - **Apply** (`Apply.tsx`, 词语应用): one flip-card per vocab word that has `sentenceBank` entries — front shows a blanked example sentence (`tingxieBlankWord()`, literal substring replace) + English gloss, back reveals the word.
  - **Practice** (`Practice.tsx`, 听写练习): two phases in one queue — vocab (auto-speaks the word via `speakText()` when each card appears, not on click) then, once that queue empties, sentences (no auto-speak) — the reducer swaps in the sentence-phase queue internally, so the component only dispatches `PRACTICE_START` once per visit.
  - Apply/Practice share a **front-shrink/back-requeue queue mechanic**: a correct self-grade drops the current item off the front; a miss moves it to the back so it resurfaces later the same pass — not persisted between visits.
- **Custom review** (`TingxiePicker.tsx`, 自由复习): multi-select checkboxes over the lesson index; on start, fetches every selected lesson and pools them (`pooledTingxieReview()` — samples up to `TINGXIE_REVIEW_VOCAB_COUNT`/`TINGXIE_REVIEW_SENTENCE_COUNT` items, merges every selected lesson's `sentenceBank` in full, uncapped) into one synthetic `TingxieActiveContent` fed straight into Apply or Practice. The Learn tab and its BP award are hidden/skipped entirely in this mode — there's no per-lesson "visit" for pooled content.
- **BP**: `TINGXIE_BP_AWARD` in `data/pet.ts` (`VOCAB_LEARN`/`SENTENCE_LEARN`: 10, `APPLY`: 10, `PRACTICE`: 20 — carried over from the source app's point values). Each award fires at most once per mount, guarded by a plain `useRef` in the awarding component (not reducer state) — since Learn/Apply/Practice remount fresh every time the student navigates back into them, replaying an activity re-earns BP, matching the source app.
- **Sound**: flips/tabs/nav need no explicit call (they're real `<button>`s or `.tingxie-flip-card`, both matched by `App.tsx`'s global click listener). `Sound.ding()`/new `Sound.miss()` (see Sound below) for correct/incorrect self-grades and sentence-order checks; `Sound.gift()` for BP-award-on-completion.
- **`TingxieFlipCard`'s back face contains real `<button>`s** (TTS, self-grade), so its outer clickable region is a `<div role="button" tabIndex={0}>`, not a `<button>` — nesting a button inside a button is invalid HTML (the same constraint `PetHeroCard` used to have). Its click handler calls `e.stopPropagation()` where needed so a click on an inner button doesn't also toggle the flip.
- **Icon decoration**: `sentence.icon` (a Lucide icon name from the source data) is mapped to an emoji via `tingxieIconEmoji()`'s lookup table in `data/tingxie.ts` (with a `✨` fallback for unmapped names); `sentence.color` (a Tailwind class) is kept on the type for JSON fidelity but never read.

### Pet / BP layer (`src/data/pet.ts` + `src/state/PetContext.tsx`)
`PetProvider` holds `PetState` in `useState`, persisted to `localStorage` under `PET_KEY` (`hanyuPracticePet_v1`) on every change; `usePet()` exposes `{ pet, awardBP, buyItem, giveItem, renameOwl, recordQuestionsCompleted }`.

- **Mood is derived, never stored as a live value**: `pet.moodAtCheckpoint` + `pet.lastFedAt` is a fixed pair, and `computeCurrentMood()` decays from that pair fresh on every call (not a decay tick) — this is what makes time-based neglect work without a server, and avoids compounding rounding error from repeatedly decaying an already-decayed number. `growth` is monotonic and completely decoupled from mood/decay.
- **BP** is awarded via `awardBP()`, called from `Quiz.tsx` for MCQ/Fill-in (immediately on grading) and for Long-Answer/Writing-Constrained (from the self-check "✓" handler, guarded by a `bpAwarded` flag on the result item so re-toggling doesn't double-pay).
- **Bag/inventory**: `PetState.inventory` is a `Record<shopItemId, quantity>`. `buyItem()` deducts BP and adds to inventory; it does *not* touch growth/mood. `giveItem()` is the only thing that applies a `ShopItem`'s growth/mood effect (and decrements inventory) — called from `Bag.tsx` once that item's throw animation lands, never directly from the Shop. `giveItem()` also logs a `"fed"` achievement, plus an `"evolved"` one if the growth crosses into a new `PetStage` (computed against the `pet` already in scope, read before the `setPet` updater runs, so logging isn't tied to the updater's StrictMode-double-invoke internals).
- **`recordQuestionsCompleted(n)`**: pure increment of `PetState.questionsLifetime`, called once per session from `Result.tsx` — kept arithmetic-only (no achievement logic inside it) so the milestone check can be computed from the pre-call value without reading a stale/batched value back out of context.
- **Naming**: `PetState.name` (default `""`, shown as a placeholder prompt until set), edited via `renameOwl()` (trims, caps at 12 chars).
- Cross-device sync (accounts, Supabase — `@supabase/supabase-js` is already a dependency) is an intentionally separate, not-yet-built later phase; `PetState`'s flat, serializable shape is designed so a future sync layer can push/pull it without a local data-model rewrite.

### Owl art (`OwlArt.tsx` + `pet.ts`)
One static PNG per stage × mood bucket lives in `public/owl/` (`owl-<stage>-<mood>.png`, e.g. `owl-baby-happy.png` — 6 stages × 4 moods = 24 assets, `owlSpritePath()`). A stage/mood combo can instead have a hand-animated **MP4** (H.264 + AAC, sound muxed into the video's own audio track — not a separate audio file) that `OwlArt` prefers over the PNG when present, driven by the `ANIMATED_OWL_VARIANTS` allowlist in `pet.ts` (currently `"egg-very_happy"`, `"baby-very_happy"`, `"egg-sad"`, and `"egg-neutral"`, with more of the 24 combos to follow — note `"egg-sad"`/`"egg-neutral"` have no PNG fallback anymore, their source PNGs were deleted when the video replaced them, unlike the first two which still keep theirs). The `<video>` has no `loop` (plays once, holds the last frame) and is only unmuted when `OwlArt`'s `playSound` prop is set — on the Home hero card, the Owl screen, and the Bag/"Feed" screen, i.e. everywhere the pet is a primary focus of the screen. `OwlArt` forwards a ref to its root element so `Bag.tsx`'s throw animation can target the owl's on-screen position.

### Sound (`src/lib/sound.ts`)
Everything is synthesized via the Web Audio API — no audio files (aside from the owl MP4's own track). Each effect has a deliberately distinct timbre so they don't get confused: `click()` (filtered-noise tap, generic UI clicks — wired up globally in `App.tsx` via a document-level click listener on `button, .option-label, .tingxie-flip-card`), `ding()` (warm detuned-oscillator bell arpeggio, correct quiz answers), `purchase()` (metallic square-wave "coin" clink, Shop buys), `gift()` (rising triangle-wave glissando, giving an item to the owl in the Bag, and reused for Tingxie's BP-award-on-completion), `applause()` (randomized/tapering noise-burst claps, 100% quiz score), `encourage()` (soft descending 2-note chime, sub-100% score), `miss()` (soft lowpass-filtered descending triangle-wave thud — the app's only "wrong answer" sound, used by Tingxie's incorrect self-grades/sentence-order checks; Quiz.tsx has no equivalent, it's silent on incorrect answers).

### History, achievements, and stats (`src/state/history.ts`, `src/state/achievements.ts`, `src/lib/stats.ts`)
- `history.ts` persists the last 50 session summaries to `localStorage` under `HISTORY_KEY` (`hanyuPracticeHistory_v2`; bump this key if the stored shape changes, to avoid crashing on old data). Each `HistoryEntry` has an `id` (assigned on save; `loadHistory()` lazily backfills `id` onto any pre-existing entries that predate the delete feature) so `Home.tsx` can delete individual rows or clear all of them.
- `achievements.ts` persists up to the 30 most recent `Achievement`s to `localStorage` under `ACHIEVEMENTS_KEY` (`hanyuPracticeAchievements_v1`), written via `logAchievement()`. Dedup rules differ by type: `"fed"` is never deduped (every genuine feed logs); `"missionComplete"` recurs at most once per calendar day (`dateKey`-scoped); `"questionsMilestone"`/`"evolved"` can each only genuinely be earned once ever (`questionsLifetime`/`growth` are both monotonic), so they're deduped by milestone number / stage key forever, not just for the day.
- `stats.ts` is the shared home for date-bucketing/derived-stat logic used across the dashboard: `dateKey()` (local-calendar-day key, DST-safe — not raw ms division), `getTodayStats()`, `getStreak()`, `formatRelativeTime()`, plus the Today's Mission helpers `READING_MISSION_CATEGORIES`, `isLessonMissionComplete()`, `getReadingMissionCount()`, `areAllMissionsComplete()`.

### Styling (`src/styles/styles.css`)
Single global stylesheet (the "scholar's-study" design system), theme-aware via `@media (prefers-color-scheme: dark)` overriding the same CSS custom properties (`--primary`, `--ink`, `--bg`, `--card-bg`, `--border`, shadow tokens, etc.) defined on `:root`. No CSS modules/CSS-in-JS — components just reference global class names.
